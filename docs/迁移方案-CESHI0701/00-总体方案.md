# CESHI0701 能力移植方案（P0 + P1）

> 目标：将 CESHI0701-main（AI 能力治理平台）的核心能力移植到当前测试平台。
> 核心诉求：记忆中心 + AI 对话（可通过对话调用已登记的测试智能体；浏览器执行需审批并留痕，不开放任意本地程序执行）。

## 一、框架一致性核对（关键前提）

经核对 `ui/package.json`、`pyproject.toml`、CESHI0701 的 `CLAUDE.md`，两个项目框架**完全不一致**：

| 层 | 当前项目 | CESHI0701 | 是否一致 |
|---|---|---|---|
| 后端 | Python 3.13 · FastAPI · SQLAlchemy 2 · Alembic · PostgreSQL · MongoDB | NestJS 11 · Prisma 6 · MySQL 8 · Redis 7 | ❌ |
| 前端 | Next.js 14 · React 18 · shadcn/ui(Radix) · Tailwind · SWR | Vue 3 · Element Plus · Pinia · Vite | ❌ |

**决策（遵循用户要求）**：一律用**当前项目框架**重写实现，**不引入任何新框架**（尤其前端不引入 Vue / Element Plus）。
CESHI0701 只作为「业务逻辑与数据模型的参考蓝本」，不复制其代码文件，只提取业务逻辑用 Python / React 重写。

**当前项目已具备的基础设施（无需新增框架）**：
- 后端：`redis`、`python-jose`(JWT)、`httpx`、`sqlalchemy`、`sse-starlette`(SSE 流)、`bcrypt`(密码哈希)
- 前端：Radix UI 全套、SWR、lucide-react、react-markdown、Monaco 编辑器、sonner(toast)

> ⚠️ 实测修正：`pyproject.toml` 虽声明 `passlib[bcrypt]`，但 passlib 1.7.4 与环境中的
> bcrypt 5.0.0 不兼容（`module 'bcrypt' has no attribute '__about__'`，会导致启动崩溃）。
> 阶段一已改为**直接调用 `bcrypt` 库**做哈希/校验，不再经 passlib。

## 二、当前项目分层约定（移植须遵循）

- 分层：`models/`(SQLAlchemy) → `repositories/`(BaseRepository) → `services/`(业务) → `api/v2/`(路由) → `schemas/`(Pydantic)
- 主键：`UUIDMixin`（PostgreSQL UUID）+ `TimestampMixin`（created_at/updated_at）
- 响应：统一 `SuccessResponse[T]` / `PaginatedResponse[T]`
- 依赖注入：`api/deps.py` 中定义 `XxxServiceDep`、`CurrentUserIdDep`、`DbSessionDep`
- 路由注册：`api/__init__.py` 中 `api_router.include_router(...)`
- 现有认证是占位：`get_current_user_id()` 返回默认用户 ID（`settings.default_user_id`）——本次将真实化。

## 四、阶段一：用户认证与权限（P0-3）✅ 已实现

参考 CESHI0701：`server/src/modules/base`（auth/user/role/menu/department）。

**后端实际落地**（`backend/app/`）：
- models：`role.py`(含 Role + UserRole + RoleMenu 三表)、`menu.py`、`department.py`(含 Department + Position)；`user.py` 增 `password_v/status/name/nick_name/head_img/phone/remark/department_id/position_id`
- schemas：`auth.py`、`user_admin.py`、`role.py`、`menu.py`、`department.py`
- services：`auth_service.py`(登录/JWT双token/Redis/权限预热/校验)、`user_admin_service.py`、`role_service.py`、`menu_service.py`、`department_service.py`(含 Position)、`rbac_seed_service.py`(启动幂等种子)
- security：`security_utils.py`(bcrypt 哈希 + JWT 签发/解码)
- config：`redis_client.py`(真实 Redis + 进程内内存后端)；`settings.py` 增 `jwt_access_expire/jwt_refresh_expire/redis_*` 及 `redis_use_memory` 本地开关、`default_admin_username/password`
- api/v2：`auth.py`、`users_admin.py`、`roles.py`、`menus.py`、`departments.py`(含 positions)，并在 `api/__init__.py` 注册
- middleware：`auth_guard.py`(FastAPI 依赖 `CurrentUserDep` + `require_perms(...)` 权限门控)
- 迁移：`alembic/versions/0010_add_rbac_tables.py`（已 upgrade head）

> 与原计划的差异（有意为之）：
> - 未新建 RBAC 专用 repository，service 直接用 SQLAlchemy `select`（RBAC 逻辑简单，避免过度分层）。
> - `auth_guard` 采用**依赖注入**而非装饰器；`deps.py` 的 `get_current_user_id` 占位**保留未删**（现有业务接口仍兼容），新接口用 `CurrentUserDep`。
> - 密码哈希用 `bcrypt` 直连（见基础设施修正说明）。

**前端实际落地**（`ui/`，Next.js + shadcn，无新框架）：
- app：`login/page.tsx`、`admin/users/page.tsx`
- providers：`AuthProvider.tsx`(认证上下文 + `useAuth` + `hasPerm`，已挂入 `app/layout.tsx`)
- components：`auth/require-auth.tsx`(路由守卫)、`admin/user-form-dialog.tsx`、`admin/reset-password-dialog.tsx`
- lib：`auth.ts`(token 存储 + 401 跳转)、`api/client.ts`(注入 Authorization + 401 处理)、`api/auth.ts`(认证/用户/角色/菜单 API)

> 前端差异：认证上下文合并进 `AuthProvider.tsx`（未单独建 `hooks/use-auth.ts`，`useAuth` 由该文件导出）。
> `admin/roles|menus|departments` 页面**暂未实现**（对应后端 API 与 `api/auth.ts` 封装已就绪），本阶段仅打通「用户管理」端到端；如需可在验收后补齐。

**验收标准**：能登录、颁发/刷新 token、分配角色、受保护 API 无 token 返回 401。
**验收结果**：后端 10 项联调全通过 + 经前端代理端到端登录通过，详见 `01-阶段一-认证与权限.md`。
