# 项目工作台导航实施计划

## 目标

在不修改系统总览内容、现有配色和项目标识模型的前提下，将当前“全局菜单下追加项目功能”的导航改为全局工作区、项目工作台和平台管理三种互斥侧栏，并确保所有入口连接现有真实业务。

## 实施范围

1. 新增纯函数导航规则，统一判断工作区、项目功能分组、页签和项目切换地址。
2. 改造 `MainLayout` 与 `Sidebar`，进入项目后完整切换为项目工作台，返回后恢复全局工作区。
3. 为测试设计、测试执行、质量分析增加页级分组页签，复用已有业务路由。
4. 新增项目智能测试页面，复用现有对话能力并锁定当前项目。
5. 新增项目设置页面，调用现有项目查询和更新接口完成真实数据读写。
6. 保持已有项目直达地址兼容，不修改数据库字段和后端项目接口。

## 风险控制

- 项目切换必须保留当前功能后缀，避免用户被强制带回项目首页。
- `/projects/agent-tasks` 和 `/projects/spaces` 必须继续识别为全局页面，不能误判为项目标识。
- 项目详情子路由（运行详情、计划等）应正确高亮所属分组并保留现有页面行为。
- 智能测试传给智能体的项目标识必须来自路由，不能被页面内选择器改写。
- 项目设置只开放现有接口支持的名称和描述，避免出现无法落地的配置项。

## 验证方式

1. Node 单元测试：路由识别、功能分组、页签映射和同功能切换项目。
2. TypeScript 类型检查与 Next.js 生产构建。
3. 浏览器业务测试：登录、全局到项目切换、各业务分组与页签、项目间切换、项目智能测试、项目设置修改并恢复、返回全局、平台管理。
4. 检查关键 API 状态、浏览器控制台错误、页面布局和移动端侧栏基本行为。
