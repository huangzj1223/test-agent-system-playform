# 智能体测试系统全局界面与首页设计说明

## 1. 设计目标

本次改版面向两类核心用户：

- 测试负责人和质量经理需要在进入系统后快速判断整体质量状态、跨项目风险、自动化闭环效率和需要人工决策的事项。
- 测试工程师需要快速找到自己的待办、正在执行的智能体任务、失败结果、待审核修复和最近使用的项目。

首页采用“上半屏管理全貌，下半屏个人工作台”的结构。页面不再以统计卡片堆叠为主体，而以智能体协作状态和可执行决策为核心。

## 2. 产品定位

产品应呈现为“智能质量控制中心”，而不是普通测试管理系统或通用数据看板。用户需要感受到智能体正在持续完成需求解析、用例生成、脚本生成、自动执行、失败诊断、修复和验证。

核心差异化表达：

1. 智能体的协作关系可观察。
2. 自动测试闭环的状态可追踪。
3. 风险判断带有原因和建议动作。
4. 管理视角与个人工作视角在同一首页中连续呈现。

## 3. 整体视觉方向

采用“冷静的智能蓝图”风格：浅冷灰工作区、深靛蓝导航、白色数据表面，辅以青色、荧光绿、琥珀色和珊瑚红状态信号。

### 3.1 色彩系统

| 角色 | 建议色值 | 用途 |
| --- | --- | --- |
| 工作区背景 | `#F3F5FA` | 全局页面基础背景 |
| 主表面 | `#FFFFFF` | 表格、面板、弹窗和表单 |
| 次级表面 | `#EAEDF5` | 分组背景和悬停状态 |
| 导航底色 | `#232741` | 左侧主导航 |
| 导航激活 | `#373C61` | 当前模块和当前项目 |
| 主操作色 | `#626CF4` | 主要按钮、选中状态和关键连线 |
| 智能体运行色 | `#2BC8C4` | 运行中、数据流和在线状态 |
| 闭环完成色 | `#A7D436` | 成功、完成和自动修复 |
| 风险提醒色 | `#F2B84B` | 注意、待确认和人工审核 |
| 阻塞告警色 | `#F0645A` | 失败、阻塞和高风险 |
| 主文字 | `#202438` | 标题和正文 |
| 次文字 | `#687084` | 说明和辅助信息 |

颜色只用于表达层级和状态，不使用大面积高饱和渐变。主界面保持浅色，深色只用于导航和首页的智能体协作核心画布。

### 3.2 形态与层次

- 全局圆角统一为 6 到 8 像素。
- 页面区块采用细边框和克制阴影，不使用悬浮大卡片铺满页面。
- 数字不使用霓虹文字阴影；运行流、节点状态和聚焦交互可以使用轻微发光。
- 图标统一使用 `lucide-react`。
- 产品界面只显示中文，必要的技术标识符除外。
- 字号不随视口宽度缩放，桌面正文以 14 像素为主。

## 4. 全局应用框架

### 4.1 左侧导航

左侧导航宽度约 220 像素，使用深靛蓝底色，分为四层：

1. 产品标识与系统名称。
2. 全局入口：系统总览、智能体任务、项目空间。
3. 当前项目入口：项目洞察、测试用例、API 测试、Web 测试、渗透测试、测试运行、测试计划、测试报告、全栈分析。
4. 底部入口：系统状态、设置和用户信息。

项目列表不在主内容区重复展示。项目切换器位于导航上部，支持搜索、收藏和进入全部项目。

### 4.2 顶部栏

顶部栏使用浅色半透明表面，与内容区连续。包含：

- 当前页面标题和所属项目。
- 全局搜索或命令入口。
- 智能体运行状态。
- 通知、帮助和用户菜单。

避免顶部栏与左侧导航形成完整的大块深色区域。

### 4.3 内容区

内容区采用自适应网格，桌面端最大内容宽度约 1720 像素。页面级标题、时间范围和主要操作固定在内容区首行。表格、筛选器和工具栏沿用相同的表面、边框和交互状态。

## 5. 首页信息架构

### 5.1 首页首行

显示“质量智能网络”标题、数据更新时间、智能体在线状态和“发起智能任务”主操作。右侧允许切换统计时间范围。

首行下方使用一条紧凑指标带展示真实聚合数据：

- 活跃项目数。
- 测试资产总量。
- 当前运行任务数。
- 待人工处置数。
- 最近周期通过率。

指标必须来自后端接口或现有实体聚合。缺少数据时显示“待接入”，不得通过固定公式估算质量成熟度、覆盖率或自动化率。

### 5.2 智能体协作星图

这是首页的主视觉和主要交互区，占桌面端上半屏约三分之二宽度。

中心节点为“质量中枢”，周围按闭环阶段组织智能体节点：

- 需求解析。
- 测试设计。
- 用例和脚本生成。
- 自动执行。
- 结果分析。
- 失败修复。
- 回归验证。

节点展示状态、任务数量和异常数量。连线表达任务流向，只有运行中的链路使用轻微流动动画。点击节点打开任务抽屉，显示关联项目、开始时间、当前步骤、产物和可执行操作。

如果当前后端只能提供部分任务数据，星图仍保留完整阶段结构，无法获取的阶段显示“暂无运行任务”，不生成虚假任务。

### 5.3 今日质量简报与风险解释器

位于星图右侧，由三类内容组成：

- 高风险变化：受最近变更影响的模块、项目和用例。
- 闭环进展：已分析、已修复、待验证和待审核数量。
- 决策建议：可直接执行的建议，例如补充用例、重跑任务或阻断发布。

每条建议需要包含原因、影响范围、置信状态和操作按钮。没有风险数据时显示健康状态和最近一次检查时间。

### 5.4 全局项目战情

使用紧凑表格或矩阵展示重点项目，不再使用重复的大项目卡片。每行包含：

- 项目名称和负责人。
- 当前阶段。
- 用例和脚本资产。
- 最近执行结果。
- 阻塞风险。
- 智能体正在进行的任务。
- 进入项目操作。

默认按风险和最近活动排序，支持查看全部项目。

### 5.5 个人处置台

下半屏左侧为个人工作队列，按“需要我审核”“需要我处理”“我正在观察”分组。任务直接链接到用例、运行、失败分析或修复结果，不提供无效按钮。

### 5.6 闭环效率

下半屏中部展示测试闭环的真实效率：

- 平均失败定位时间。
- 自动修复成功率。
- 修复后验证通过率。
- 人工介入比例。

没有统计接口时显示数据接入状态和可追踪的任务数量，不计算伪指标。

### 5.7 最近活动与快捷工作入口

下半屏右侧展示最近运行、生成、分析和修复事件。快捷入口只保留高频动作：生成测试用例、解析 API 文档、创建 Web 测试、查看失败分析。

## 6. 单项目首页延续规则

点击项目后进入项目洞察页，沿用相同的视觉系统和信息逻辑，但将星图与指标限制在当前项目。单项目首页重点展示：

- 项目健康状态和发布风险。
- 测试资产结构和覆盖变化。
- 最近运行趋势。
- 失败与缺陷分布。
- 当前项目的智能体任务和待办。

全局首页解决“系统现在怎么样”，项目首页解决“这个项目为什么是这样以及下一步做什么”。

## 7. 数据与状态设计

首页需要统一的视图数据适配层，将项目、用例、运行、结果、失败分析和智能体任务数据转换成展示模型。首版优先复用现有接口，并对未接入模块显示明确空状态。

页面必须覆盖：

- 首次加载骨架屏。
- 部分接口失败的局部错误状态。
- 全部为空的新系统状态。
- 有项目但没有运行记录的状态。
- 智能体任务运行、成功、失败和等待人工确认状态。

一个区块加载失败不应导致整个首页不可用。

## 8. 响应式规则

- `1440px` 及以上：完整侧栏，星图与简报并排，下半屏三列。
- `1024px` 至 `1439px`：侧栏保持，星图全宽，简报移动到下一行。
- `768px` 至 `1023px`：侧栏折叠为图标轨道，指标和工作区两列。
- 小于 `768px`：使用抽屉导航，星图降级为阶段列表，工作区单列。

所有图表和节点画布必须有稳定高度，不因数据加载或标签变化产生布局跳动。

## 9. 实施边界

本轮实施范围：

1. 重构全局颜色、表面、导航、顶部栏和内容背景。
2. 重构系统首页的信息架构与主要交互。
3. 建立可复用的页面标题、状态指标、区块标题、数据面板和空状态样式。
4. 保持现有业务路由和页面功能不变，并让现有页面继承新的全局框架。
5. 使用真实现有数据完成首页首版；对缺失聚合能力明确显示待接入状态。

本轮不重写所有业务页面内部结构，不新增虚假的后端统计数据，也不实现与当前系统没有数据基础的发布流水线功能。

## 10. 验收标准

- 用户进入首页后，在一个屏幕内看见系统态势、智能体运行、风险和个人待办。
- 首页核心画面具有智能体测试系统的独特识别度，不像通用 BI 看板。
- 全局导航、顶部栏和内容区配色协调，不出现上黑下白的割裂。
- 所有首页数字有真实数据来源或明确标注待接入。
- 首页主要入口可点击并进入对应功能。
- 桌面和移动端无文本重叠、横向溢出和布局跳动。
- TypeScript 检查通过，并用浏览器截图验证桌面和移动视口。
