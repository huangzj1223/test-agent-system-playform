# 黑洞吸积式智能体协作星图设计

## 目标

首页智能体协作星图改为围绕“全部项目/当前项目”黑洞核心旋转的立体银河。用户一眼能够辨认出星云、旋臂、星团和不同距离的恒星，并感受到物质越靠近核心越密集、越明亮，最终向事件视界下凹和汇聚。

## 页面职责调整

- 系统总览首页只保留全局标题、指标条和全宽智能体协作星图。
- 首页移除“今日质量简报”和“全局项目战情预览”，为星图提供足够宽度和高度。
- “今日质量简报”迁入项目空间，继续消费既有 `risk_items` 和 `updated_at`，不改变接口或数据结构。
- 项目管理、跨项目处置和质量活动继续由项目空间承接。

## 视觉模型

银河使用四层空间结构：深空星场、远侧吸积盘、事件视界和近侧吸积盘。每颗星携带确定性的深度参数，远处星体更小、更暗、更冷，近处星体更大、更亮并带有限光晕。银河尘埃沿三条旋臂分布，半径采样向内偏置，使中心附近天然更密集。

吸积盘按倾斜三维平面投影。粒子深度来自旋转角的正弦值；靠近观察者的半盘提高尺寸、透明度和亮度，远侧半盘先绘制并降低对比度。径向漏斗函数在越接近中心时产生更大的垂直沉降，配合中央暗事件视界、引力透镜环和向内流动的光丝，形成黑洞吞噬造成的凹陷感。

星团不是随机均匀散点，而是沿旋臂锚定的局部高密度簇。每个星团包含冷蓝恒星、少量暖色恒星和弥散云团；星团尺寸、亮度和粒子大小同样受前后景深度控制。

## 运动与层级

- 主银河缓慢顺时针转动，星团和星尘保持同一物理旋转方向。
- 远侧吸积盘、事件视界、近侧吸积盘依次绘制，中心 DOM 核心固定在引力井位置。
- 七阶段业务节点继续按既有顺时针椭圆轨道运动，数据、状态、链接和详情逻辑不变。
- 暂停、页面隐藏和 `prefers-reduced-motion` 时停止连续运动并保留完整静态画面。
- Canvas 背景限制在约 30fps，业务节点继续使用独立 RAF，避免大画布影响交互。

## 可测试条件

- 星场种子必须包含 0～1 的深度；近景样本平均半径和透明度高于远景样本。
- 银河尘埃至少 45% 位于归一化半径 0.45 内，体现中心增密。
- 吸积投影必须返回深度、缩放、亮度和漏斗沉降；内圈沉降明显高于外圈。
- 首页源码不再包含 `QualityBrief`、`ProjectSituation` 和“全局项目战情预览”；项目空间包含 `QualityBrief`。
- 1920px 页面中星图宽度至少 1400px、高度至少 620px，今日质量简报不在首页出现。
- Canvas 像素检查需同时检测中央暗事件视界、中心附近高亮密度和下半部近景亮星。

## 技术实现

- 继续使用 Next.js 14、React 18、TypeScript、Tailwind 和 SVG，并新增 Three.js 作为星图内部的 WebGL 渲染层。
- WebGL 绘制三维旋臂粒子、星团、事件视界、引力井和吸积盘；现有 Canvas 降级为远景星云与伴星系背景，无 WebGL 时仍能显示完整静态银河。
- 仅新增 `three` 生产依赖及其 TypeScript 类型，不修改后端、数据库或 dashboard 数据契约。
- 不覆盖工作区内无关未提交修改，不自动提交或推送。
